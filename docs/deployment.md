# 배포·운영

---

## 1. 배포 형태 — Docker Compose 번들

에어갭 옵션이 요구사항이라 `docker save/load` 이미지 번들이 자연스럽고, 온프렘에 k8s 없는 곳이
많으며, 의존성(Python·cryptography·DB)이 이미지에 갇혀 **지원 비용이 가장 낮다.**

Helm 차트는 Scale 프로파일에서 후속으로 낸다 — 두 경로를 처음부터 유지하면 매니페스트·문서·
테스트가 2벌이 되고 설정 체계를 일치시키는 부담이 계속 남는다.

**저사양 호스트를 위한 도커 없는 경로**도 함께 제공한다. 의존성이 5개뿐이라 현실적이다:

```bash
pip install -e . && python -m app.main --demo
```

## 2. 배포 프로파일

| 프로파일 | 구성 | 대상 |
|---|---|---|
| **Demo** | 노트북 1대: 컨트롤 플레인 + SQLite + **목 프로바이더**(+ 선택 소형 모델) | 시연·PoC·개발자 온보딩 |
| **Starter** | 단일 호스트: 컨트롤 플레인 + SQLite + 내장 노드 1 | 소규모 실사용 |
| **Standard** | 컨트롤 플레인 호스트 + 외부 GPU 노드 2~3대 | 주력 |
| **Scale** | Postgres + 컨트롤 플레인 다중 인스턴스, Helm | 후속 |

### 2.1 Demo — LLM 없이 제품의 대부분을 보여준다

목 프로바이더는 **마지막에 붙이는 포장이 아니라 개발 중 상시 사용하는 경로다** —
실제 노드 없이 테스트를 돌리려면 어차피 필요하고, 그게 그대로 데모가 된다.

| 목으로 시연 가능 | 방법 |
|---|---|
| 테넌시·격리 | 테넌트 2개를 만들고 서로 안 보이는 것을 확인 |
| **가드 1단(패턴)** | PII 샘플 투입 → 마스킹·차단. **LLM 불필요** |
| **배치 라우팅** | 가짜 노드 여러 대 → 티어 우선순위·데이터 경계 |
| **장애 폴백** | 노드를 죽여 다른 노드로 넘어가는 것 |
| 비용 예약/정산 | 가짜 단가로 예산 소진 → 무료 경로 자동 강등 |
| 관제 UI 전체 · 알림 | 노드 그리드·큐·사용량·감사·웹훅 |

**목으로 안 되는 것**: 실제 생성 품질, 가드 2단 LLM 분류(내부 노드 전용).
2단까지 보려면 소형 모델(~1 GB) 하나를 로컬에 얹는다.

### 2.2 데모 호스트

| RAM | 데모 범위 |
|---|---|
| **4 GB** | 목 프로바이더 — 위 표 전부 |
| **8 GB** | + 소형 모델로 **가드 2단 분류 실연** (권장) |
| **16 GB** | + 중형 모델로 실제 생성까지 (CPU 추론이라 느림) |

**OS: Xubuntu LTS 권장** (또는 Ubuntu Server + XFCE).

- **Windows·macOS 배제** — Docker Desktop 이 VM 으로 ~2 GB 를 먼저 먹는다.
  컨트롤 플레인(512 MB)보다 도커가 4배 무겁다. Linux 는 네이티브라 오버헤드가 거의 0.
- Ubuntu LTS 는 Docker 공식 저장소가 1순위 지원 → 준비 중 삽질이 최소.
- GNOME(~2 GB) 대신 XFCE(~600 MB) — 4 GB 에서 데스크톱만으로 절반이 날아가는 것을 막는다.

RAM 예산(8 GB): XFCE 0.6 + 브라우저 0.8 + 컨트롤 플레인 0.5 + 소형 모델 1.5 = **3.4 GB**.

#### 데모 호스트 준비 체크리스트

| # | 항목 | 이유 |
|---|---|---|
| 1 | **절전·뚜껑 닫힘 억제** | 시연 중 뚜껑을 닫으면 노드가 죽는다 |
| 2 | 부팅 시 자동 기동 | `restart: unless-stopped`. 전원만 켜면 뜨게 |
| 3 | zram 스왑 | 4 GB 에서 모델 로드 시 결정적 |
| 4 | mDNS(`*.local`) | 현장 네트워크가 매번 바뀐다 |
| 5 | **디스크 암호화(LUKS)** | 암호화된 프롬프트와 마스터 KEK 를 같은 디스크로 들고 다닌다 |

```bash
# 1번
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
# /etc/systemd/logind.conf → HandleLidSwitch=ignore
```

5번은 데모라서 넘어갈 항목이 아니다 — 제품 문서가 "KEK 는 백업과 분리" 를 요구하면서
데모 관행이 그 반대면, 설치처가 따라 하는 것은 관행 쪽이다.

## 3. 설치

```bash
tar xzf llm-controlcenter-<ver>.tgz && cd llm-controlcenter
./preflight.sh                          # 포트·디스크·메모리·도커 버전. 실패 사유를 사람 말로
docker compose --profile tls up -d      # 공개망에 붙는다면 tls 프로파일로
```

**`--profile tls` 를 빼면 프록시가 안 뜬다.** 그러면 TLS 종단도, 플랫폼 관리 면
(`/v1/platform/*`) 차단도 없이 앱이 그대로 노출된다. 역할 검사는 프록시 없이도 돌지만
노출을 줄이는 것은 프록시의 몫이다 — 신뢰 네트워크 안이 아니라면 프로파일을 켠다.
차단 규칙은 번들의 [`tls/nginx.conf`](../tls/nginx.conf) 에 들어 있다(topology §2).

### 3.1 부트스트랩 (최초 기동)

1. **마스터 KEK 생성** → `/keys` 에 저장, **1회만 표시**하고 백업 안내
2. **플랫폼 관리자 계정 생성** — **기본 자격증명 없음**, 랜덤 생성 후 1회 표시
3. 첫 테넌트 생성 + 첫 노드 등록(즉시 프로브)
4. 테넌트 로케일에 맞는 **가드 로케일 팩 자동 활성화**
5. 베이스라인 규칙을 대부분 `audit` 등급으로 시작 — 처음부터 `block` 이면 도입 첫날 막힌다

`./doctor.sh` 로 언제든 진단: 노드 도달성·디스크 여유·키 존재·스키마 버전·설정 유효성.

### 3.2 노드 등록 (엔드포인트 등록형)

관제 UI 에서 URL · `data_boundary` · 용량을 입력하면 끝이다. **노드에는 아무것도 설치하지 않는다.**
등록 즉시 프로브해서 도달성·모델 인벤토리·버전을 수집하고, 실패하면 등록 화면에서 바로 알린다 —
설치 후에 조용히 안 붙는 것이 제품에서 가장 나쁜 경험이다.

### 3.3 다중 워커 (지원 구성)

기본은 1 프로세스다. 제출·조회 처리량이 부족하면 **API 워커를 늘린다** — 같은 호스트,
같은 DB 파일을 공유한다. 동시성 계약은 architecture.md §11 에 있다.

```bash
python -m app serve --port 8610                     # ① 스케줄러 포함 — 정확히 하나
python -m app serve --port 8611 --no-scheduler      # ② API 전용
python -m app serve --port 8612 --no-scheduler      # ③ API 전용
```

**`--no-scheduler` 를 빠뜨리면 안 된다.** 워커마다 레인 루프가 돌면 같은 잡이 중복
배치되고, metered 경로면 두 번 과금된다. 스케줄러는 **정확히 하나**다.

프록시가 셋을 라운드로빈으로 물린다. `/healthz` 가 인증 없이 응답하므로 그대로 헬스체크에 쓴다.

**전제 두 가지**:

- **같은 호스트의 로컬 파일시스템.** SQLite 의 WAL 잠금은 NFS·SMB 에서 신뢰할 수 없다.
  호스트를 넘기려면 Postgres(Scale 프로파일)다.
- **워커 수를 노드 동시성에 비해 보수적으로.** 동기 경로 두 곳(`/v1/embed`, 가드 2단
  분류)은 워커에서 배치하고 그 슬롯 장부는 프로세스 로컬이다 — 워커 N 개면 그 두 경로에
  한해 노드 동시성이 최대 N 배까지 초과될 수 있다(architecture.md §11, 부채 표).
  이 경로가 부하의 큰 몫이 아니라면 문제가 되지 않는다.

오프라인 번들에 이미지 tar + 정적 자산(외부 CDN 금지) + 선택적 모델 가중치를 담는다.

## 5. 업그레이드·마이그레이션

- 스키마는 **ADD COLUMN 전용** — 추가·NULL 기본값만, 재작성·삭제 금지
- 설정 스키마에 버전을 박고 기동 시 호환성 검사. 모르는 키는 거부가 아니라 경고(전진 호환)
- 롤백은 이미지 태그 되돌리기. 스키마가 전진 호환이라 구버전이 신버전 DB 를 읽는다
- 업그레이드 전 자동 백업(단, 원문 암호문 제외)

## 6. 시크릿

| 항목 | 보관 |
|---|---|
| 마스터 KEK | 파일 마운트 또는 env. **백업과 분리** |
| 테넌트 DEK | KEK 로 래핑해 DB 에 |
| 서비스 토큰 | 해시만 저장. 발급 시 1회 표시 |
| 클라우드 API 키 | **플랫폼 단위.** 노드 선언의 `api_key_env` 가 환경변수 이름을 가리키고, 값은 프로세스 환경에 있다 |
| 노드 인증 헤더 | 같은 방식 — `auth_header_env` |

**토큰 수명주기 API**(발급·회전·만료·폐기 + 감사)가 1급 기능이다.
소비자 추가가 "YAML 편집 + 재기동" 인 제품은 성립하지 않는다.

### 클라우드 키가 테넌트별이 아닌 이유 — 그리고 그 대가

노드는 **플랫폼 자원**이고 공유 풀이다. 노드 1개 = 키 1개이므로 "테넌트별 키" 는 현
노드 모델과 구조적으로 양립하지 않는다. 테넌트별로 키를 가르려면 노드-키 바인딩 모델부터
다시 정의해야 하고, 그 요구는 `tenant_affinity` 전용 노드로 이미 부분적으로 표현된다 —
**전용 노드에 전용 키를 걸면 그것이 곧 테넌트별 키다.**

대가를 감추지 않는다:

| 대가 | 뜻 |
|---|---|
| 프로바이더 청구서 상 귀속이 플랫폼 단위 | 테넌트별 비용은 이 제품의 `usage` 로만 보인다. 프로바이더 콘솔에서는 한 덩어리다 |
| 키 폐기 단위가 플랫폼 | 한 테넌트 때문에 키를 갈면 그 노드를 쓰는 전 테넌트가 함께 끊긴다 |
| 키가 KEK 로 래핑되지 않는다 | 환경변수라 DB 유출에는 안 실리지만, 프로세스 환경을 읽을 수 있으면 그대로 보인다 |

판정 근거는 [design-decisions.md](design-decisions.md) D5.

## 7. 노드 구간 보안

Ollama 는 기본 무인증이다. 전제를 명시한다.

- 기본 전제: **`internal` 노드는 신뢰 네트워크에 있다**(사설망·VPN). `preflight` 가 경고한다.
- 옵션: 노드별 `auth_header_env` + TLS. 노드 설정에 선언.
- **`data_boundary: external` 노드는 TLS·인증을 필수로 강제한다** — 공개망을 지난다는 뜻이므로.

전제를 안 적으면 설치처가 노드를 공개망에 열어두고 "제품이 알아서 지켜주겠지" 로 넘어간다.

**컨트롤 플레인 자신의 노출**은 별개다 — 앞단 프록시가 담당하고, 번들의
[`tls/nginx.conf`](../tls/nginx.conf) 가 플랫폼 관리 면을 404 로 막는다(§3, topology §2).

## 8. 백업·복원·DR

**복원 절차가 없으면 백업은 없는 것과 같다.**

| 절차 | 내용 |
|---|---|
| 백업 | 자동. **원문 암호문 제외**. DB + 설정. KEK 는 별도 위치 |
| 복원 | `./restore.sh <backup>` — 스키마 버전 호환 검사 후 복원. **역할 오버라이드가 되돌아간다는 경고를 띄운다** |
| DR | **KEK 분실 = 암호문 영구 손실.** 부트스트랩에서 KEK 백업을 강제 안내 |
| 검증 | 백업 무결성 정기 확인 + 복원 리허설 |

백업에서 원문 암호문을 빼는 이유: `raw_prompt_retention_days` 로 7일 뒤 암호문을 지워도,
**30일 전 백업을 복원하면 지워졌어야 할 원문이 되살아난다.** 보관 기간 설정이 백업 앞에서
무의미해진다. 테넌트 DEK 폐기(crypto-shredding)가 이 문제를 구조적으로 푸는 유일한 수단이다.

## 9. 운영 인터페이스

| 항목 | 내용 |
|---|---|
| **알림** | **상태 전이에서만**. 노드 오프라인·복구, 모델 승인 대기, 예산 소진(80%·100%), 가드 차단 급증, 분류 실패율 상승 |
| 알림 채널 | 웹훅(Slack/Teams 호환) + SMTP. **실패가 파이프라인을 죽이지 않는다** |
| **메트릭** | Prometheus/OpenMetrics `GET /metrics` |
| **로그** | 구조화(JSON) stdout. **프롬프트·응답 본문·비밀 미포함** |
| **진단 번들** | `./doctor.sh --bundle` — 설정(비밀 마스킹)·스키마 버전·노드 상태·최근 오류 |

알림 3원칙: 상태 전이에서만 / 기동 시 "복구됨" 을 보내지 않는다 / 비밀·프롬프트·응답을 담지 않는다.

관제 센터가 알림 없이는 관제를 못 한다 — **"사람이 모르면 조용히 멈추는 지점"** 이 알림의 기준이다.
